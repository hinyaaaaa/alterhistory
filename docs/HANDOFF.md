# 引き継ぎ書（次チャットへの指示）

このファイルは「次に何をすべきか」に特化する。設計の全体像は `ARCHITECTURE.md`、
`.map` 形式の仕様は `MAP_FORMAT_SPEC.md` を見ること。ここでは重複を避け、
**未実装のもの・中途半端なもの・決めずに仮置きしたもの**だけを列挙する。

作業を始める前に、必ず `npm test` を実行して全スイートが通ることを確認すること。
`npm test` は合成マップ（`tests/.samples/`、実行のたびに生成）だけで完結し、常に緑であること。
実マップは消滅済み。実マップ専用の検証項目は `npm run test:compat`（`SAMPLES_DIR` に実マップのフォルダを指定）にだけ含まれる。
CI（`.github/workflows/ci.yml`）が `npm ci` → `npm test` → `npm run build` と、`dist` がソースと一致しているかを確認する。
`dist/app.js` は `js/` から `npm run build` で作る成果物。ソースが正で、dist だけを直さないこと。

## 追加済み：UI簡素化・歴史ログ・名前の自動生成・.ahmap（最新）

**「歴史をつくる」ボタンとパネル（`ui/history-builder.js`）は廃止した。** 機能は次のとおり移した。
- 国家・文化・宗教の作成 → 設定メニューの一覧ウィンドウの「＋ 追加」「🎲 おまかせ領土つき」（`ui/entity-list-window.js`、中身は従来どおり `app/builder-actions.js`）。属州は国家の詳細の「新しい属州」。
- 政体・種類・起源・**最高神** などの設定 → 国家・文化・宗教の詳細パネル（`ui/profile-fields.js` を `editor-panel.js` から呼ぶ）。最高神は🎲で名前を作れる。
- 経済・貿易 / 旅・ゾーン → 設定メニューの独立ウィンドウ（`ui/work-windows.js`）。
- 「地図編集」ボタンは上部バーに常時表示。
- 全ウィンドウ（浮かぶウィンドウ・国家の詳細・地図編集）は四辺・四隅のつまみで大きさを変えられる（`ui/windows.js` の `makeResizable`）。

**名前の自動生成**: 同盟・ゾーン（種類別の語尾）・最高神・時代の名前を、文化の系統に合わせてランダムに作る（`core/names/katakana.js` の `generate*Name`、`core/edit/naming.js` の `suggestLabel`）。空欄のまま作成すると自動で付き、🎲で作り直せる。

**歴史ログ**（`core/edit/history-log.js`）: 建国・改名・宗教の誕生・最高神や政体の変更・遷都・都市の建設・領土の変動・ゾーンの発生などを、世界の年月つきで `ext.data.historyLog` に記録する。Undo/Redo で一緒に戻る。領土の塗り足しは同日・同対象なら1件にまとめる（`mergeKey`）。記録の配線は `app/edit-actions.js` の `commitEv`/`withEvent`。**新しい操作を足したら、ここに出来事を足すこと。**

**クロニクルの年表は圧縮・要約・省略をしない**（どんなに長くなってもよい。歴史ログにも件数の上限は無い）。過去の出来事は「その日付の時点の国名」で書く（`makeStateNameAt`。改名は歴史ログの `ref`、古い地図は統合記録の当時の名前から推定）。「（消滅）」は滅んだ後の日付にだけ付け、戦争・同盟の一覧では存続中だった国に「（のち消滅）」を添える。講和条約は割譲・賠償・併合・従属・条件をすべて書く（`describeTreaty`）。戦力は記録がある戦闘にだけ書く。

**クロニクルは .md の1ファイルだけ**（`io/chronicle.js` の `chronicleToMarkdown`）。「1. 年表」が年→月の順に全アクションと戦争・同盟・外交を並べる。JSON 版の書き出しはUIから廃止（`serializeChronicle` はテスト用に残している）。

**保存形式は独自の `.ahmap`**（`io/native-map.js`。gzip した JSON。セル配列は RLE）。Azgaar の `.map` は**読み込みのみ**。`io/azgaar-writer.js` は互換テスト用に残してあるが UI からは使わない。`loader.js` が先頭の `{` で形式を判定する。旧「Azgaar＋拡張行」形式のファイルも読める。

## 未実装（要望のうち、まだ手を付けていないもの）

### 1. 地図の自動生成（最大の未実装部分）
地形・河川・気候・都市・道路・国家・宗教の生成は何も無い。現状は
「Azgaarで作った地図を読み込んで編集する」ことしかできず、ゼロから地図を
作ることはできない。これは当初の要望の中心の一つだったが、「編集を先に」
という指示で後回しにした経緯がある。着手する場合は `MAP_FORMAT_SPEC.md` の
「pack の形は保存されていない」節と `core/geometry.js` の grid→pack 再構築を
先に理解すること（生成順序に依存する）。

### 2. 名前の生成（カタカナの仮生成は実装済み。残りの課題）
実装済み: `core/names/katakana.js`（7系統の音節組み合わせ）、`core/edit/naming.js`（既存名と被らない提案・
文化ごとの系統・「仮」フラグ）。都市・属州・国家・宗教・文化に使える。UIは都市/属州/文化/宗教/国家作成の
ダイアログと編集パネルの 🎲。文化パネルで「名前の系統」を選べる。

- **仮生成は「仮」の音節表ベース**。実在言語の音韻規則の再現ではない。系統の追加・語彙の調整は
  `NAME_STYLES`（heads/mids/tails）を編集するだけでよい。`tests/naming.test.mjs` が全系統を検査する。
- 既存の Azgaar 名前ベース（`namesbase`）は読み書きのみで、生成には使っていない。
- 川・山・湖などの地物名、マーカー名、人名（統治者）は未対応。

  仮名の一覧表示や一括確定も未実装（`naming.js` の `listProvisional` はある）。

### 4. 境界線・頂点そのものの手動編集
今の編集は「セル単位の塗り替え」（`core/edit/paint.js`）のみ。国境線を

### 5. 書き出し画像の凡例・スケールバー
画面上の凡例（サイドバー）はあるが、`io/exporter.js` で作るPNG/SVGには

### 6. 重い処理のWeb Worker化

## 実装したが「仮置き」の数値（実データに基づかない）

以下は「動くようにするため」に置いた値で、実データや理論的根拠に基づかない。
プレイしてバランス調整が必要になる可能性が高い。

### 経済成長（`core/sim/economy.js`）
```
年間人口成長率 = 0.6%（技術Lv1） 〜 2.1%（技術Lv10）、ロジスティック成長
産業力係数     = 0.05（技術Lv1） 〜 0.86（技術Lv10）、人口1000人あたり
人口の上限     = 初期人口の3倍（固定）
```
技術水準は国家に `techLevel`（1〜10、既定3）として保持されるが、**技術水準を
上げる手段がUIに無い**（`core/edit/attributes.js` 経由の自由記述属性とは別物）。
現状は`techLevel`を直接編集するUIが存在しない。技術水準を変える場合は
コンソールから `map.pack.states[id].techLevel = 5` のように直接いじるしかない。
**ここは次チャットで真っ先にUI化すべき欠落点。**

### 兵科の戦闘力係数（`core/sim/units.js`）
```
歩兵1（人）: power=1        機甲(台): power=8     航空(機): power=15
海軍(隻): power=40          特殊部隊(人): power=4  先端技術(人): power=6（技術Lv6以上）
核(発): power=500（技術Lv9以上）
```
歩兵を1とした相対値。海軍が1隻=歩兵40人相当、核が1発=歩兵500人相当という
比率は感覚で決めたもの。ドクトリン補正（`DOCTRINES`）も同様に仮置き。

### 戦闘判定（`core/sim/battle.js`）
```
勝率決定 = 戦力比較 × 乱数(0.85〜1.15)
勝者の損耗 = 3%〜12%（戦力差が大きいほど小さい）
敗者の損耗 = 15%〜40%（戦力差が大きいほど大きい）
```

### 徴兵ペース（`core/sim/military.js` の `planAnnualConscription`）
年間の徴兵数は `(人口/1000) × (rural+urban係数) × 0.15` + `産業力配分`。
0.15という係数は「緩やかに増える」ことだけを狙った仮の値。

## UIの既知の粗さ（動くが磨けていない）

- 各パネルは再描画のたびに `replaceChildren()` でDOMを作り直す。フォーカスとスクロール位置は `js/ui/safe-render.js` が復元するが、
  `keepScroll` はクラス名・タグ名・順番でスクロール領域を特定するので、DOM構造を変えると別の領域に戻る可能性がある。
  年表や戦争履歴が大きくなったら、主要な一覧だけ差分更新にする。
- 浮動ウィンドウ（`js/ui/windows.js`）はネイティブの `<dialog>` ではない。フォーカス移動・モーダル性・キーボード操作は自前。
  複数の窓が重なったとき、いま作業している窓が分かりにくい。
- 戦争・軍事・外交・講和の窓を行き来する場面がある。戦争を文脈の中心にして、そこから部隊・同盟・講和条件を開く形にしたい。
- 設定メニューの項目が多い。「世界／国家間／シミュレーション／高度」のように分類したい。
- Chronicle の書き出しは .md と .json の2ファイルを同時にダウンロードする。ブラウザによっては複数ダウンロードが制限される。

## テストで踏んだ落とし穴（同じ罠を踏まないために）

次チャットが同種の機能を追加する際、以下は過去に実際にハマった。

1. **`??` と `||` の混在は構文エラー。** `a ?? b || c` は書けない。
   `a ?? (b || c)` のように必ず括弧で明示する。
2. **`querySelector`と`getElementById`を混同しない。** このプロジェクトの
   `$()`ヘルパーは`getElementById`用。CSSセレクタを渡すバグを複数回起こした。
   CSSセレクタには`q()`（`querySelector`）を使う。
3. **`<input>`要素の値は`textContent`に含まれない。** `card.textContent.includes(name)`
   のようなテストは、名前が`<input value="...">`で表示されている場合は常に
   偽になる。`input.value === name`で判定すること。
4. **`render()`が要素を作り直すUIでは、クリック後に取得したDOM参照は古くなる。**
   `button.click()`の後、同じ`button`変数のプロパティを見ても更新されない。
   クリック後は改めて`querySelector`等でDOMから取り直すこと。
5. **Pythonの`str.replace`で`assert`が失敗すると、その回のファイル書き込みは
   一切行われない。** 複数の置換をまとめて1つの`open(...).write()`で書く
   スクリプトは、途中の`assert`で例外が起きると全体が失敗し、ファイルは
   一切変更されない（部分適用されない）。ドキュメント更新でこれを踏み、
   「前回書いたはずの内容が消えている」ように見える事象が実際に起きた。
   置換前に`grep`等で対象文字列の実在を確認してから流すこと。
6. **実データは公式仕様の「模範解答」ではない。** 2つのサンプルファイルは
   ユーザーが手動編集した痕跡があり（属州が国境沿いに薄い、宗教の保存値と
   実測がずれている等）、最初から矛盾を含む。「実データと一致しない」＝
   「自分の実装が間違っている」と早合点せず、まず矛盾が編集前から存在した
   ものか(`core/edit/integrity.js`のbaseline機構はこのために作った)を疑うこと。

## 追記: 実データ検証で見つけた・直した不具合（最新セッション）

実データ（Azgaar 1.114.2 と 1.139.11 の2ファイル）で、UIスモークテスト一式と `tests/newfeatures.test.mjs` を実行して確認済み。

## 追記: ズーム連動ラベル・レイヤー整理・フォント（第4弾）
- ズーム連動ラベル（`render/layers/places.js`）: 倍率 z = 現在の倍率 ÷ 全体表示の倍率。首都は常に表示、都市は人口の多い順に z が上がるほど現れる（`labelZoom`: 首都0、上位から 1.15〜約6.3 倍。記号は名前の0.72倍の位置で先に現れる）、属州名は 1.7〜2.3 倍でふわっと出て 7.5〜10 倍で消える、国名は 4.5〜8 倍で薄れて場所を譲る。重なり回避の優先順: 首都 > 国名（首都名と重なるときだけ上下にずらす）> 上位15%の都市 > 属州名 > 残りの都市。
- 閾値は 30都市の合成地図で調整したもの。実マップ（919都市）で密度が合うか要確認（`labelZoom` の 1.15 / 5.2 / 0.85、`topN` の 0.15）。
- 表示モード: `view.burgLabels` = auto（ズーム連動・既定）/ all / capitals / none。`labels.burgs` に "auto" を渡すと LOD、true は従来どおり全都市。書き出し（PNG/SVG）も同じ描画なので、全体表示の書き出しでは首都中心になる。
- レイヤー: 上部バーに「レイヤー ▾」を新設（プリセット 政治/地形/標高、色分け、下地、地図の要素、名前の表示）。色分け・下地・都市名は区切りボタンで、裏に元の `<select>`（#sel-overlay / #sel-base / #sel-burg-labels）を隠して残してある（既存のテストと互換）。地図編集パネルは「ツール」だけにした。メニューは同時に1つだけ開き、外を押す／Esc で閉じる。
- フォント（`render/fonts.js`）: 地図の文字は Shippori Mincho（明朝）、画面は Noto Sans JP。Google Fonts から読み込み、読めない環境では游明朝・游ゴシック等に切り替わる。日本語 Web フォントは文字範囲ごとの分割配信なので、`ui/fonts-sync.js` が地図の名前に使う文字を指定して読み込み、終わったら再描画する。見出し・題名も明朝、国名・首都名は字間を広げた太字、属州名は字間の広い細字（`ctx.letterSpacing`。SVG 書き出しは letter-spacing 属性）。
- この環境にはインターネットが無いため、Web フォント自体の描画は未確認（フォールバックの明朝／ゴシックでの確認のみ）。
