# 引き継ぎ書（次チャットへの指示）

このファイルは「次に何をすべきか」に特化する。設計の全体像は `ARCHITECTURE.md`、
`.map` 形式の仕様は `MAP_FORMAT_SPEC.md` を見ること。ここでは重複を避け、
**未実装のもの・中途半端なもの・決めずに仮置きしたもの**だけを列挙する。

作業を始める前に、必ず `npm test` を実行して全スイートが通ることを確認すること。
`npm test` は合成マップ（`tests/.samples/`、実行のたびに生成）だけで完結し、常に緑であること。
実マップは消滅済み。実マップ専用の検証項目は `npm run test:compat`（`SAMPLES_DIR` に実マップのフォルダを指定）にだけ含まれる。
CI（`.github/workflows/ci.yml`）が `npm ci` → `npm test` → `npm run build` と、`dist` がソースと一致しているかを確認する。
`dist/app.js` は `js/` から `npm run build` で作る成果物。ソースが正で、dist だけを直さないこと。

## 追加済み：反乱・分離（HoI4 風・いちばん新しい）

属州が離反すると、別の国家として成立し、軍が割れて元の国との内戦になる。理想は「補給や物資の細かい設定がない HoI4」なので、領土・都市・属州・軍の割れ方と、内戦という1つの戦争だけで表し、補給は持たない。

- `planDeclareIndependence`（`core/edit/sovereignty.js`）を、複数の属州をまとめて切り離せるように拡張（`provinceIds`、先頭が中心の属州）。新国家に `parentState`（分離元）を持たせ、`cause: "rebellion"` を主権ログに残す。年表は「反乱: ○○が△△から離反し…（内戦）」と書き分ける（平和的な独立は従来の文面）。
- `core/edit/rebellion.js`: `breakawayCandidates`（首都の属州・都市の無い属州は除き、首都から遠い順）／`pickBreakawayProvinces`（自然発生用に、属州の2〜4割を選ぶ。元の国に必ず属州が残る）／`planSplitArmy`（反乱側の領土にいる部隊はそのまま移り、残りの部隊からは領土の割合〈1〜4.5割〉の兵力を首都の「反乱軍」にまとめる。兵力の合計は変わらない）。
- 戦争形態 `civil`（内戦）を追加（`WAR_TYPES`、`civilOnly: true`）。手で宣戦する形態の一覧には出さない。両軍とも全部隊が参戦し、決着は既存の講和（鎮圧・独立承認など）で決める。
- `simActions.rebel({provinceIds, name, color, civil})`（`app/sim-actions.js` の `breakaway`）: 独立 → 色 → 軍の分割 → 内戦の開戦 → 戦争名「○○内戦」→ 地図のマーカーまでを `atomic` で「全部成功か全部取り消し」にし、Undo も1回。失敗したら例外を投げる。`civil: false` なら戦争にならない平和的な独立。
- 自然発生: 独立の出来事は `provinceIds`（複数）と `civil` を持つ。民意が低いほど内戦になりやすい（55 + (55 − 民意)/100 %、上限90%）。自然発生の新国家の名前は「仮」の印つき。
- UI: 属州の「独立させる」を「反乱・独立…」に変更し、`ui/rebellion-window.js`（属州をチェックで複数選択・名前・色・形〈内戦／平和的な独立〉→「反乱を起こす」）を開く。確定するまで何も起きず、キャンセル／×なら何も起きない。国家の基本情報に「分離元」を表示する。
- テスト: `tests/rebellion.test.mjs`（選び方・軍の割れ方・内戦・年表・Undo・途中で失敗したら全部取り消し・自然発生）、`tests/rebellion-ui.smoke.test.mjs`（ウィンドウの導線）。
- **まだ入れていないこと**: 内戦中に反乱側が外国に支援を求める・親国の同盟国が自動参戦しない設定（いまは既存の同盟の拘束力どおりに参戦する）・内戦の勝敗で「鎮圧すると反乱側の属州を取り戻し、国が消える」ことの自動化（講和ウィンドウで併合を選ぶ形）。

## 追加済み：共通の初期設定ウィンドウ

新しい国家・文化・宗教・属州は、必ず共通の「初期設定」ウィンドウ（`ui/setup-window.js`）で入力して「確定」を押したときにだけ作られる。入力中の名前の試行錯誤や、キャンセル／×で閉じた場合は、地図にも年表にも何も残らない。

- `app/setup-actions.js` の `create(kind, spec)` が、作成・色・政体／種類／最高神・起源・おまかせ領土・首都を `store.transaction` で「全部成功か全部取り消し」にし、年表には最終内容で `created-<kind>` を**1件だけ**残す（詳細に政体・領土のセル数・首都）。Undo も1回。途中の塗り・首都・プロフィール設定は個別には記録しない。
- 確定後の改名・政変は、これまで通り別の出来事（`rename-*` など）として記録される。
- 入口: 一覧ウィンドウの「＋ ○○を追加」（属州もここから作れる。所属国を選ぶ）／塗りツールの「＋ 新しい○○を作る…」／国家の詳細の「＋ 属州を追加…」。「🎲 おまかせ領土つき」ボタンは廃止し、ウィンドウの「領土」欄（あとで塗る／おまかせ 小・中・大）に統合した。
- 名前が空欄のまま確定すると、おまかせの名前（政体名・神名もいっしょに）になる。名前は確定済みなので「仮」の印は付かない。
- `planAddEntity` / `planAddProvince` に `color`（#rrggbb、不正なら自動）を追加。
- 旧 `editActions.addEntity` / `addProvince` / `builderActions.create` は API として残るが、UI からは使わない（`ui/history-builder.js` は未使用の旧ファイルで、どこからも読み込まれていない）。
- テスト: `tests/setup-create.test.mjs`（1件だけ記録・Undo 1回・失敗で全取り消し）、`tests/builder-ui.smoke.test.mjs`（キャンセル／×／確定の導線）。

**まだ入れていないこと**: 同盟・ゾーン・時代・都市・マーカーは、この共通ウィンドウに載せていない（同盟・時代は元から入力フォームで確定する形、ゾーン・都市・マーカーは地図クリックで置く形）。載せるなら次の候補。

## 追加済み：原子性・当時の事実・年表ウィンドウ・外交の正本・自然発生イベント（いちばん新しい）

方針（変えない）: 乱数は固定しない／年表は圧縮・要約・省略しない（件数の上限なし）／保存は独自の `.ahmap`、Azgaar の `.map` は読み込みのみ／ボタンを増やさず既存のウィンドウと設定メニューに寄せる／新しい操作は `app/edit-actions.js` の `commitEv`（または `withEvent`）で歴史ログにも足す。

**着手前の確認で分かったこと**
- 外部レビューの「最新CIが赤」は正しかった。原因は廃止済みの `builder-panel` を探す `tests/builder-ui.smoke.test.mjs`。テストを現行の導線（設定メニュー→一覧ウィンドウの「＋ 追加」）に書き換え、使われていない `js/ui/history-builder.js` を削除した。閾値は緩めていない。
- 指示書の `app/...` は、実際は `js/app/...`。

**A. 複合操作の原子化**
- `core/store.js` に `transaction(label, fn)` を追加。途中で例外が出たら、適用済みの変更を逆順に戻し、履歴にも残さず、例外を投げ直す（`beginBatch` の中でも入れ子にできる）。`makeCommand` の `apply` も、途中の部品が失敗したら適用済みの部品を戻す。
- `app/sim-actions.js` の複合操作（戦闘・会戦・開戦・講和＋併合・隠密作戦・核作戦・軍の引き上げ・召集・戦況の進行）を `atomic()`（= transaction）に載せ替えた。`signTreaty` の「併合の失敗を握りつぶす catch」は無くした。併合が失敗すれば、講和ごと取り消されて、失敗が画面に出る。
- テスト: `tests/atomic.test.mjs`。

**B. 当時の事実で記録**
- 戦争（`names`）・戦闘（`attackerName`/`defenderName`/`aPower`/`dPower`）・条約（`terms.names`）・同盟（`memberNames`）・外交ログ（`aName`/`bName`）に、当時の国名を保存。
- 手で戦わせた戦闘（`attack`/`recordBattle`）は、もともと戦力を持っていた。開戦時に作る想定の戦闘ログには、開戦時の両陣営の戦力（陸＋海＋空）を `powerBasis: "war-start"` つきで入れた（1戦ごとの戦力ではない点に注意）。
- `io/chronicle.js` は保存された名前を優先し、無い古いデータだけ `makeStateNameAt` の推定に戻す（`stateAtFor`）。「（消滅）」「（のち消滅）」の印は、いまの状態から足す。
- テスト: `tests/history-facts.test.mjs`。

**C. 読み込み時の検査**
- `io/loader.js` の `inspectLoaded` が、`validateMap`・`checkIntegrity`・新設の `checkHistoryRefs`（`core/edit/integrity.js`）・外交表の食い違いを実行し、**警告として**出す（開けなくはしない）。件数は1行にまとめる。
- `validateMap` に、宗教の参照範囲と、数値列の非数値（NaN/null）の検査を追加。Azgaar の数値列に数値でない値があれば「0として読み込んだ」旨の警告を出す。
- 新しい形式版の `.ahmap` は、対応版・コピーを取る案内つきの警告を出す。
- テスト: `tests/load-validation.test.mjs`。

**D. 年表ウィンドウ**
- 設定メニューの「📜 年表」（`ui/timeline-window.js`）。種類・国・年・語で絞り込み、項目を押すと地図がその場所へ移り、手書きの出来事も足せる。全件を表示し、仮想スクロール（見える行だけを描く）で速度を保つ。
- 年表の組み立ては `io/chronicle.js` の `timelineOf` に切り出し、`buildTimeline(map)` で単独に呼べる。各項目は `cell`（移る場所）と `stateIds`（関係する国）を持つ。
- 歴史ログ（`core/edit/history-log.js`）の出来事は、`date`・`cell`・`states` を持てる。マーカーの設置・移動・編集・削除、ノートの書き換え、旅の作成、戦争の細かい動き（`war.events`）、隠密作戦・核作戦も年表に載る。
- テスト: `tests/timeline-window.smoke.test.mjs`。

**E. 外交の正本**
- `core/edit/relations.js` の `relationOf` が正本。順序は 戦争 > 従属 > 同盟 > 外交表。外交表（`states[].diplomacy`）は、導いた値を写す表（Azgaar 互換の保存先）として残す。貿易・年表は `relationOf` を読む。`planSetDiplomacy`/`getRelation` は、外交表そのものを扱う従来のAPIのまま。
- 国家統合（`planMergeStates`）が、続いている同盟・従属・戦争を統合先に付け替える（`retargetParts`）。2か国未満になった同盟は解消、敵と味方が1つの国になる戦争は終結（白紙和平）。終わった戦争・解消済みの同盟は書き換えない。
- テスト: `tests/relations.test.mjs`。

**F. 戦争の整合**
- 開戦時に作る戦闘ログは `war.forecast`（想定）に、実際に起きた戦闘は `war.battles` に分けた。古い保存（`forecast` が無い）は `battles` に混ざったまま読める。再判定の理由は戦闘ではなく `war.events`（`kind: "reevaluate"`）に残る。
- 戦争を500回ずつ自動で回す `tests/war-statistics.test.mjs`（乱数は固定しない）。互角なら攻撃側41%・防御側40%・引き分け19%、2倍の差で強い側が約76%、4倍で100%。

**G. 自然発生イベント**
- `core/sim/natural-events.js`（何が起きるかの決定、疫病・反乱の計画）と、`app/sim-actions.js` の `applyNaturalEvents`（独立・分派を、全部成功か全部取り消しで実行）。年が変わるときに `app/time-actions.js` から呼ぶ。
- オン／オフと頻度（まれ・ふつう・多い）は、時間設定ダイアログ（上部バーの年月 → 「自然に起きる出来事」）。地図に保存（`ext.data.naturalEvents`）。既定はオン・ふつう。
- 乱数は固定しない。疫病・反乱・分派は歴史ログ、独立は主権の記録として年表に載る。
- テスト: `tests/natural-events.test.mjs`。

**修正の追記（その後）**
- 統合された国の部隊: 部隊IDが統合先と重ならないよう振り直し、所属（`state`）も統合先に直すようにした（`planMergeStates`）。以前は、双方に0番の部隊があると、IDが重複していた。
- 外交表の食い違い: 外交・同盟ウィンドウに、食い違いがあるときだけ「同盟・従属・戦争に合わせて直す」が出る（`editActions.diplomacyMismatchCount` / `reconcileDiplomacy`）。普段は何も出ない。Undoできる。
- 疫病: セルの人口（`pop`）・都市の人口・国／属州／宗教の集計をいっしょに減らす。疫病のあとも整合性の検査は崩れない。
- 戦争の長さ（`estimateDurationMonths`）: 僅差・膠着ほど長く、圧勝ほど短く、ばらつきは対数正規（短期決着も長期戦もまれに出る）。平均は元の手触りを保つよう係数0.68で調整。互角で中央値14か月、10%点8〜90%点27か月。圧勝（4倍）は平均で約17%短い。
- 自然発生イベントの確率: 反乱の基本確率を0.04→0.025にし、民意が低いときの上乗せに上限（2.5倍）を付けた。以前は、民意20の世界で、国あたり約10年に1回起きていた。いまは、民意がどれだけ低くても、1国あたり ふつう で年6.25%、多い で年12.5%が上限。疫病は世界全体で約19年に1回、独立は不安定な国で数十年に1回、宗教の分派は約40年に1回。**確率は、数値を見て決めた初期値で、実際の遊びの手触りは確認していない。**

**まだ直せていない点・注意**
- `.ahmap` を無圧縮で保存するのは、`CompressionStream` が無い環境（jsdom）だけ。
- 外交表の食い違いは、読み込み時に警告するだけで、自動では直さない（直す入口は外交・同盟ウィンドウ）。
- 統合した国の部隊を、続いている戦争の召集リスト（`muster`）に自動では加えない（統合元の召集リストは捨てる）。
- 自然発生イベントの確率は、実際に遊んでの調整が必要かもしれない（`BASE_RATE`、`REBELLION_BOOST_MAX`）。

## 追加済み：UI簡素化・歴史ログ・名前の自動生成・.ahmap（最新）

**「歴史をつくる」ボタンとパネル（`ui/history-builder.js`）は廃止した。** 機能は次のとおり移した。
- 国家・文化・宗教の作成 → 設定メニューの一覧ウィンドウの「＋ 追加」「🎲 おまかせ領土つき」（`ui/entity-list-window.js`、中身は従来どおり `app/builder-actions.js`）。属州は国家の詳細の「新しい属州」。
- 政体・種類・起源・**最高神** などの設定 → 国家・文化・宗教の詳細パネル（`ui/profile-fields.js` を `editor-panel.js` から呼ぶ）。最高神は🎲で名前を作れる。
- 経済・貿易 / 旅・ゾーン → 設定メニューの独立ウィンドウ（`ui/work-windows.js`）。
- 「地図編集」ボタンは上部バーに常時表示。
- 全ウィンドウ（浮かぶウィンドウ・国家の詳細・地図編集）は四辺・四隅のつまみで大きさを変えられる（`ui/windows.js` の `makeResizable`）。

**名前の自動生成**: 同盟・ゾーン（種類別の語尾）・最高神・時代の名前を、文化の系統に合わせてランダムに作る（`core/names/katakana.js` の `generate*Name`、`core/edit/naming.js` の `suggestLabel`）。空欄のまま作成すると自動で付き、🎲で作り直せる。

**歴史ログ**（`core/edit/history-log.js`）: 建国・改名・宗教の誕生・最高神や政体の変更・遷都・都市の建設・領土の変動・ゾーンの発生などを、世界の年月つきで `ext.data.historyLog` に記録する。Undo/Redo で一緒に戻る。領土の塗り足しは同日・同対象なら1件にまとめる（`mergeKey`）。記録の配線は `app/edit-actions.js` の `commitEv`/`withEvent`。**新しい操作を足したら、ここに出来事を足すこと。**

**クロニクルの年表は圧縮・要約・省略をしない**（どんなに長くなってもよい。歴史ログにも件数の上限は無い）。過去の出来事は「その日付の時点の国名」で書く（`makeStateNameAt`。改名は歴史ログの `ref`、古い地図は統合記録の当時の名前から推定）。「（消滅）」は滅んだ後の日付にだけ付け、戦争・同盟の一覧では存続中だった国に「（のち消滅）」を添える。講和条約は割譲・賠償・併合・従属・条件をすべて書く（`describeTreaty`）。戦力は記録がある戦闘にだけ書く。

**クロニクルは .md の1ファイルだけ**（`io/chronicle.js` の `chronicleToMarkdown`）。「1. 年表」が年→月の順に全アクションと戦争・同盟・外交を並べる。JSON 版の書き出しはUIから廃止（`serializeChronicle` はテスト用に残している）。

**保存形式は独自の `.ahmap`**（`io/native-map.js`。gzip した JSON。セル配列は RLE）。Azgaar の `.map` は**読み込みのみ**。`io/azgaar-writer.js` は互換テスト用に残してあるが UI からは使わない。`loader.js` が先頭の `{` で形式を判定する。旧「Azgaar＋拡張行」形式のファイルも読める。

## 追加済み：歴史ビルダー（「楽に作る」と「好きに設定」の両立）

`README.md` の「歴史をつくる」節を参照。設計方針は**段階的開示**: 全部おまかせでも、1つだけ手で決めても、途中で混ぜてもよい。細かい設定は消さずに畳む。
テスト: `tests/builder.test.mjs`（領土・首都のロジック）、`tests/builder-ui.smoke.test.mjs`（jsdom）。Chromium(Playwright)で画面も確認済み。

同時に直した既存の不具合:
- 塗りツール中の左ドラッグで、地図まで一緒にパンしていた（`ui/map-view.js`）。いまは塗りツール中は左ドラッグでパンしない（中ボタンか、選択ツールで）。
- 凡例が編集（国の追加・塗り替え・Undo）で更新されなかった（`ui/legend.js`）。
- 技術水準・ドクトリンをUIから変えられなかった → ビルダーの「詳しく」から変更可能に。

残っていること:
- おまかせ領土は「空き地（無所属の陸）」しか使わない。空き地が無い世界では手で塗る必要がある（その旨を画面に出す）。
- 属州・都市・マーカー・地形は、かんたん作成の対象外（従来の地図編集／国家タブで操作）。

### 兵科の戦闘力係数（`core/sim/units.js`）

歩兵1（人）: power=1        機甲(台): power=8     航空(機): power=15

## テストで踏んだ落とし穴（同じ罠を踏まないために）

次チャットが同種の機能を追加する際、以下は過去に実際にハマった。

1. **`??` と `||` の混在は構文エラー。** `a ?? b || c` は書けない。
   `a ?? (b || c)` のように必ず括弧で明示する。
2. **`querySelector`と`getElementById`を混同しない。** このプロジェクトの
   `$()`ヘルパーは`getElementById`用。CSSセレクタを渡すバグを複数回起こした。
   CSSセレクタには`q()`（`querySelector`）を使う。
3. **`<input>`要素の値は`textContent`に含まれない。** `card.textContent.includes(name)`
   のようなテストは、名前が`<input value="...">`で表示されている場合は常に
   偽になる。`input.value === name`で判定すること。
4. **`render()`が要素を作り直すUIでは、クリック後に取得したDOM参照は古くなる。**
   `button.click()`の後、同じ`button`変数のプロパティを見ても更新されない。
   クリック後は改めて`querySelector`等でDOMから取り直すこと。
5. **Pythonの`str.replace`で`assert`が失敗すると、その回のファイル書き込みは
   一切行われない。** 複数の置換をまとめて1つの`open(...).write()`で書く
   スクリプトは、途中の`assert`で例外が起きると全体が失敗し、ファイルは
   一切変更されない（部分適用されない）。ドキュメント更新でこれを踏み、
   「前回書いたはずの内容が消えている」ように見える事象が実際に起きた。
   置換前に`grep`等で対象文字列の実在を確認してから流すこと。
6. **実データは公式仕様の「模範解答」ではない。** 2つのサンプルファイルは
   ユーザーが手動編集した痕跡があり（属州が国境沿いに薄い、宗教の保存値と
   実測がずれている等）、最初から矛盾を含む。「実データと一致しない」＝
   「自分の実装が間違っている」と早合点せず、まず矛盾が編集前から存在した
   ものか(`core/edit/integrity.js`のbaseline機構はこのために作った)を疑うこと。

- ズーム連動ラベル（`render/layers/places.js`）: 倍率 z = 現在の倍率 ÷ 全体表示の倍率。首都は常に表示、都市は人口の多い順に z が上がるほど現れる（`labelZoom`: 首都0、上位から 1.15〜約6.3 倍。記号は名前の0.72倍の位置で先に現れる）、属州名は 1.7〜2.3 倍でふわっと出て 7.5〜10 倍で消える、国名は 4.5〜8 倍で薄れて場所を譲る。重なり回避の優先順: 首都 > 国名（首都名と重なるときだけ上下にずらす）> 上位15%の都市 > 属州名 > 残りの都市。
- 閾値は 30都市の合成地図で調整したもの。実マップ（919都市）で密度が合うか要確認（`labelZoom` の 1.15 / 5.2 / 0.85、`topN` の 0.15）。
- 表示モード: `view.burgLabels` = auto（ズーム連動・既定）/ all / capitals / none。`labels.burgs` に "auto" を渡すと LOD、true は従来どおり全都市。書き出し（PNG/SVG）も同じ描画なので、全体表示の書き出しでは首都中心になる。
- レイヤー: 上部バーに「レイヤー ▾」を新設（プリセット 政治/地形/標高、色分け、下地、地図の要素、名前の表示）。色分け・下地・都市名は区切りボタンで、裏に元の `<select>`（#sel-overlay / #sel-base / #sel-burg-labels）を隠して残してある（既存のテストと互換）。地図編集パネルは「ツール」だけにした。メニューは同時に1つだけ開き、外を押す／Esc で閉じる。
- フォント（`render/fonts.js`）: 地図の文字は Shippori Mincho（明朝）、画面は Noto Sans JP。Google Fonts から読み込み、読めない環境では游明朝・游ゴシック等に切り替わる。日本語 Web フォントは文字範囲ごとの分割配信なので、`ui/fonts-sync.js` が地図の名前に使う文字を指定して読み込み、終わったら再描画する。見出し・題名も明朝、国名・首都名は字間を広げた太字、属州名は字間の広い細字（`ctx.letterSpacing`。SVG 書き出しは letter-spacing 属性）。
- この環境にはインターネットが無いため、Web フォント自体の描画は未確認（フォールバックの明朝／ゴシックでの確認のみ）。
