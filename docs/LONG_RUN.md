# 長期検証の記録（V5-M12）

`node --max-old-space-size=3300 tests/long/long-run.mjs <年数> [セル数] [シード] [出力JSON]`（npm test には含めない）。
環境: 1 コア・RAM 4GB のサンドボックス。世界は 6,000 セル、シード 99、開始集団 1。

- **1,000年は安定**（約 20 秒前後）。**5,000年まで整合性エラー 0**（文明状態・因果グラフ・月次履歴の全件検査を 500 年ごとに実施）。
- **決定性**: 同じシード・同じコードで、毎回同じハッシュ（再実行で 1,500 年まで一致を確認）。
- **10,000 年は完走していない。** 5,000 年（約 65 分）のところでプロセスが終了した（原因は未確定。ヒープが 2GB 前後で、RAM 4GB の環境ではメモリ不足の可能性が高い）。
- 保存サイズの目安（1,400 年・M7 テスト）: 生 78MB（イベント 6.5 万・判断 5.1 万・月次履歴 12.6MB）。.ahmap では圧縮される。

## 既知の限界と 5.x の課題
1. **メモリ**: イベント・判断記録を全件メモリに持つ。5,000 年で約 63 万イベント・31 万判断。10,000 年は 4GB では厳しい。対策案: 期間チャンクの遅延読み込み、イベント本体の圧縮表現。**削除・要約はしない**（契約）。
2. **イベントの量**: 約 17 件/年（要求・技術の伝播・国家の行動が多い）。要求イベントは再発にヒステリシス（緊張 0.5 未満で再武装）を入れて 3 分の 1 にした。さらに調整の余地がある。
3. **集団数は 2,485 で飽和**（6,000 セルの世界）。セル数を増やした場合の性能は未測定。
4. Obsidian 書き出しは全件を 1 つの ZIP に入れる。5,000 年規模は数十万ファイルになるため、範囲指定（期間・AI 判断の有無）で絞って使う。分割出力は 5.x。

## v6（WCDE）の長期測定（v6.0.0 リリース候補・未解決の課題あり）
環境・世界は上と同じ（1 コア・6,000 セル）。シード long-1、`time.advance` で 250 年ずつ。`--max-old-space-size=3000`。

| 年 | 存続国家 | イベント | AI判断 | 外交提案の記録 | 保存（生 JSON） | ヒープ | 250年の所要 |
|---|---|---|---|---|---|---|---|
| 100（別走） | — | 30,509 | 22,910 | — | 約 36MB | 340MB | — |
| 250 | 169 | 87,080 | 71,999 | 8,743 | 107.1MB | 1,120MB | 86 秒 |
| 500 | （未達） | | | | | | 250 → 500 年の途中で、プロセスが終了した（メモリ不足の可能性が高い） |

- **v5 と比べて、イベントと判断の量が約 20 倍**（v5: 約 17 件/年、v6: 約 300 件/年）。100 年時点の内訳: 国家の行動 `state_action` 34%・技術の発見 18%・技術の移転 8%・条約の締結と終了 10%。判断記録は、候補の配列が 42%（7.4MB）、観測が 18%。
- このため、**v5 の「5,000 年まで安定」は、v6 では成り立たない**。この環境での目安は、**6,000 セルで 250 年前後まで**。500 年以上は、設計の変更が必要（下記）。
- 保存は gzip 圧縮に対応した（`packSaveGz`・拡張子 `.ahw.gz`。テストで元の 1/3 未満）。ただし、メモリ（ヒープ）の問題は、圧縮では解決しない。
- 外交提案の記録は、要因を符号（ラベル表の番号）で保存して小さくした（履歴は消していない）。120 か月で約 430 件。

### 未解決（設計の判断が必要）
1. **イベント・判断の表現を、情報を落とさずに小さくする**: 判断の候補配列と観測を、列指向・共有辞書にして持つ／期間チャンクで遅延読み込みする（v5 の方針と同じ。**削除・要約はしない**）。
2. **イベントの発生量の調整**: `state_action`（国家の行動）を、判断記録と二重に持たない（行動の事実は 1 件、判断記録からイベントへの参照にする）。技術の発見・移転も、再発の抑制を入れる余地がある。
3. 上のうち、どこまでを v6.0.0 に入れるかは、利用者の判断（`V6_STATUS.md`）。
