# 長期検証の記録（V5-M12）

`node --max-old-space-size=3300 tests/long/long-run.mjs <年数> [セル数] [シード] [出力JSON]`（npm test には含めない）。
環境: 1 コア・RAM 4GB のサンドボックス。世界は 6,000 セル、シード 99、開始集団 1。

- **1,000年は安定**（約 20 秒前後）。**5,000年まで整合性エラー 0**（文明状態・因果グラフ・月次履歴の全件検査を 500 年ごとに実施）。
- **決定性**: 同じシード・同じコードで、毎回同じハッシュ（再実行で 1,500 年まで一致を確認）。
- **10,000 年は完走していない。** 5,000 年（約 65 分）のところでプロセスが終了した（原因は未確定。ヒープが 2GB 前後で、RAM 4GB の環境ではメモリ不足の可能性が高い）。
- 保存サイズの目安（1,400 年・M7 テスト）: 生 78MB（イベント 6.5 万・判断 5.1 万・月次履歴 12.6MB）。.ahmap では圧縮される。

## 既知の限界と 5.x の課題
1. **メモリ**: イベント・判断記録を全件メモリに持つ。5,000 年で約 63 万イベント・31 万判断。10,000 年は 4GB では厳しい。対策案: 期間チャンクの遅延読み込み、イベント本体の圧縮表現。**削除・要約はしない**（契約）。
2. **イベントの量**: 約 17 件/年（要求・技術の伝播・国家の行動が多い）。要求イベントは再発にヒステリシス（緊張 0.5 未満で再武装）を入れて 3 分の 1 にした。さらに調整の余地がある。
3. **集団数は 2,485 で飽和**（6,000 セルの世界）。セル数を増やした場合の性能は未測定。
4. Obsidian 書き出しは全件を 1 つの ZIP に入れる。5,000 年規模は数十万ファイルになるため、範囲指定（期間・AI 判断の有無）で絞って使う。分割出力は 5.x。
